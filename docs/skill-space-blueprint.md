# Skill-Space Blueprint

## Product Direction

Skill-Space is a local-first SkillOps desktop application for turning reusable AI agent workflows into universal skills. It manages skills created from Codex, Claude Code, OpenClaw, and Hermes Agent, then lets the user inspect, version, import, and execute those skills from one visual workspace.

The first version is personal-use only. It stores all registry data on the local D drive and defaults to full execution permissions.

## Local Data Root

Default data root:

```text
D:\Skill-Space
```

Directory layout:

```text
D:\Skill-Space\
  skills\       Published skill packages
  runs\         Run metadata and per-run state
  logs\         Runtime logs
  artifacts\    Generated files and exported outputs
  imports\      Manually imported skill archives or folders
  registry\     SQLite database and indexes
  config\       Local app and adapter configuration
```

## Desktop Application

The application should be built with Electron, React, Vite, and TypeScript.

Recommended process split:

```text
Electron main process
  - owns local filesystem access
  - owns SQLite registry
  - launches CLI adapters
  - streams run events to renderer

Renderer process
  - Liquid Glass UI
  - skill list and detail pages
  - workflow graph editor
  - run console
  - adapter health panel

Preload bridge
  - exposes typed IPC methods only
  - prevents renderer from using unrestricted Node APIs directly
```

## Visual Style

The UI should use an Apple Liquid Glass-inspired design language:

- translucent surfaces over a subtle live background
- `backdrop-filter: blur(...) saturate(...)`
- thin light borders and inner highlights
- layered inspectors, command bars, and floating controls
- responsive hover and pointer-driven reflection
- restrained colors with strong contrast and legible text

The first screen is the actual workspace, not a marketing page.

Primary layout:

```text
Left rail        Agent, skill, run, automation navigation
Top glass bar    Search, current agent, sync status, quick run
Main canvas      Skills grid, workflow graph, or run console
Right inspector  Selected skill metadata, parameters, versions, permissions
Bottom drawer    Logs, events, artifacts
```

## Language And Localization

The interface defaults to Simplified Chinese and supports English in Settings.

Locale requirements:

- default locale: `zh-CN`
- supported locales: `zh-CN`, `en-US`
- all navigation labels, buttons, status text, validation messages, run states, and empty states must use i18n keys
- skill content stays in its original language unless the user explicitly asks to translate it
- agent prompts generated by Skill-Space should follow the UI language by default, while preserving code, commands, file paths, and schema keys

## Universal Skill Package

Skill-Space must remain compatible with existing `SKILL.md` skills. The portable skill itself should follow the common skill convention: a folder named after the skill, a required `SKILL.md`, YAML frontmatter with `name` and `description`, concise Markdown instructions, and optional `scripts/`, `references/`, `assets/`, and `agents/openai.yaml`.

Skill-Space-specific registry, workflow, permission, and adapter metadata should live under a hidden `.skillspace/` extension folder. This keeps the skill usable by Codex, Claude Code, OpenClaw, Hermes, and other agents that only understand the basic `SKILL.md` convention.

```text
my-skill\
  SKILL.md
  agents\
    openai.yaml
  scripts\
  references\
  assets\
  .skillspace\
    manifest.json
    workflow.yaml
    inputs.schema.json
    outputs.schema.json
    permissions.json
    adapters.json
```

`SKILL.md` is the canonical human and agent-readable instruction file.

Minimum `SKILL.md`:

```markdown
---
name: repo-review-and-pr-summary
description: Review repository changes and generate a concise PR summary. Use when the user wants an agent to inspect code changes, identify risks, and produce a PR-ready summary.
---

# Repo Review And PR Summary

Follow this workflow when reviewing repository changes:

1. Inspect the current diff and relevant files.
2. Identify correctness risks, missing tests, and behavior changes.
3. Run the configured verification commands when available.
4. Produce findings first, then a concise PR summary.
```

`.skillspace/manifest.json` is the Skill-Space manifest:

```json
{
  "schemaVersion": "skillspace.skill.v1",
  "id": "repo-review-and-pr-summary",
  "name": "Repo Review and PR Summary",
  "version": "1.0.0",
  "description": "Review repository changes and generate a concise PR summary.",
  "entry": "SKILL.md",
  "workflow": ".skillspace/workflow.yaml",
  "inputSchema": ".skillspace/inputs.schema.json",
  "outputSchema": ".skillspace/outputs.schema.json",
  "permissions": ".skillspace/permissions.json",
  "adapters": ".skillspace/adapters.json",
  "runtimes": ["claude", "codex", "openclaw", "hermes"],
  "defaultRuntime": "claude",
  "tags": ["coding", "review"]
}
```

## Workflow Format

`.skillspace/workflow.yaml` describes the visual graph and execution plan:

```yaml
schemaVersion: skillspace.workflow.v1
nodes:
  - id: capture_context
    type: agent_step
    title: Capture Context
    prompt: Read the workspace context and summarize the task constraints.

  - id: run_checks
    type: command
    title: Run Checks
    command: npm test

  - id: final_output
    type: agent_step
    title: Final Output
    prompt: Produce the final result and list artifacts.

edges:
  - from: capture_context
    to: run_checks
  - from: run_checks
    to: final_output
```

Supported node types for MVP:

- `agent_step`
- `command`
- `approval`
- `file_read`
- `file_write`
- `script`

## Permissions

The user selected full permissions by default. The app should still record permissions explicitly so a stricter mode can be added later.

```json
{
  "mode": "full",
  "filesystem": {
    "read": ["*"],
    "write": ["*"]
  },
  "commands": {
    "allow": ["*"],
    "approvalRequired": []
  },
  "network": {
    "enabled": true,
    "domains": ["*"]
  },
  "secrets": {
    "allowReferences": true,
    "storePlaintext": false
  }
}
```

Secrets are never written into skill packages. Skill packages may only reference secret names.

## Agent Adapters

All agents should be called through a common adapter interface:

```ts
export interface AgentAdapter {
  id: "claude" | "codex" | "openclaw" | "hermes";
  label: string;
  checkHealth(): Promise<AgentHealth>;
  execute(request: SkillRunRequest): AsyncIterable<RunEvent>;
  cancel(runId: string): Promise<void>;
}
```

Default runtime order:

1. Claude Code
2. Hermes Agent
3. OpenClaw
4. Codex

Known local adapter commands:

```text
Claude Code:
claude -p "<compiled prompt>" --output-format stream-json

Hermes Agent in WSL:
wsl -d Ubuntu-24.04 -- /home/jaygo/.local/bin/hermes -z "<compiled prompt>"

OpenClaw:
openclaw agent --local --message "<compiled prompt>" --json

Codex:
currently unavailable because the global codex npm shim points to a missing @openai/codex module
```

## Skill Creation Modes

Skill-Space should support three creation paths.

### Agent Workflow Capture

After a workflow is completed in Codex, Claude Code, OpenClaw, or Hermes, the user invokes the installed `skill-space` skill. The skill reads the current session context or exported transcript, extracts the reusable workflow, and generates a new Skill-Space package.

Required generated files:

- `SKILL.md`
- `.skillspace/manifest.json`
- `.skillspace/workflow.yaml`
- `.skillspace/inputs.schema.json`
- `.skillspace/outputs.schema.json`
- `.skillspace/permissions.json`
- `.skillspace/adapters.json`

### User-Created Workflow

The app lets the user create a workflow from scratch through Flow Studio. The generated graph is saved to `.skillspace/workflow.yaml`, and the app scaffolds the compatible `SKILL.md`.

### Manual Import

The app can import:

- a folder containing `SKILL.md`
- a folder containing `.skillspace/manifest.json`
- a legacy folder containing `skill.json`, which should be migrated to `.skillspace/manifest.json`
- a `.zip` skill package
- a standalone `SKILL.md`
- markdown or YAML workflow notes that can be converted into a skill draft

Imported items first land in:

```text
D:\Skill-Space\imports
```

After validation, they are normalized into:

```text
D:\Skill-Space\skills\<skill-id>
```

```text

skill_files

```

Run states:

```text

running
waiting_for_agent
succeeded
failed

```

## Execution Flow

```text
User selects skill
  -> app renders input form from inputs.schema.json
  -> user selects agent, defaulting to Claude Code
  -> app compiles SKILL.md + workflow.yaml + user inputs into one execution prompt
  -> adapter starts CLI process
  -> stdout/stderr stream into run_events
  -> artifacts are collected
  -> final result is stored in runs and shown in the console
```

## Build Roadmap

### Phase 1: Local Shell

- Electron app scaffold
- Liquid Glass workspace UI
- local config loading from `D:\Skill-Space\config`
- empty skill list and agent status page

### Phase 2: Registry

- SQLite registry
- scan `D:\Skill-Space\skills`
- import local skill folder or `SKILL.md`
- validate `SKILL.md` frontmatter and `.skillspace/manifest.json`

### Phase 3: Execution

- Claude Code adapter
- Hermes WSL adapter
- OpenClaw adapter
- run console with streaming logs
- per-run artifacts folder

### Phase 4: Skill Generation

- `skill-space` skill package
- session transcript importer
- workflow-to-skill compiler
- draft review before publish

### Phase 5: Flow Studio

- React Flow visual editor
- bidirectional `workflow.yaml` editing
- node inspector
- schema-driven input form

### Phase 6: Automations

- local schedules
- file watchers
- webhook triggers
- one-click rerun
